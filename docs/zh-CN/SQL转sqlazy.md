# 使用方式：聊天框输入 /SQL转sqlazy + SQL语句。为提高成功率可补充更详细的任务描述（目标、源数据、计算要求、预期结果）

示例2：/SQL转sqlazy 
SQL（postgresql）：
```
WITH 
minute_stats AS (
    SELECT
        date_trunc('minute', t::time) AS minute_start,
        (array_agg(v ORDER BY t))[1] AS first_val,
        (array_agg(v ORDER BY t DESC))[1] AS last_val,
        min(v) AS min_val,
        max(v) AS max_val
    FROM t_1742353802112
    GROUP BY 1
),
all_minutes AS (
    SELECT generate_series(
        (SELECT min(minute_start) FROM minute_stats),
        (SELECT max(minute_start) FROM minute_stats),
        '1 minute'::interval
    ) AS minute_start
),
joined AS (
    SELECT 
        m.minute_start,
        s.first_val,
        s.last_val,
        s.min_val,
        s.max_val,
        count(s.last_val) OVER (ORDER BY m.minute_start) AS grp
    FROM all_minutes m
    LEFT JOIN minute_stats s ON m.minute_start = s.minute_start
),
filled AS (
    SELECT 
        minute_start,
        first_val,
        max(last_val) OVER (PARTITION BY grp) AS end_value,
        min_val,
        max_val
    FROM joined
)
SELECT 
    to_char(minute_start, 'HH24:MI:SS') AS start,
    to_char(minute_start + interval '1 minute', 'HH24:MI:SS') AS "end",
    coalesce(
        lag(end_value) OVER (ORDER BY minute_start),
        first_val
    ) AS start_value,
    end_value,
    coalesce(min_val, end_value) AS min,
    coalesce(max_val, end_value) AS max
FROM filled
ORDER BY minute_start;
```    
目标：每分钟窗口统计。
源数据：库表t_1742353802112的t字段是时间，时间的间隔有时大于 1 分钟。
```
t	v
10:10:00	3
10:11:00	4
10:13:00	5
10:13:00	9
10:13:00	8
10:14:00	2
```
计算要求：将数据每分钟分成一个窗口，补上缺失的窗口，统计每个窗口内的 4 个指标：
    - end_value：本窗口内最后一条记录的 v 值。若本窗口无数据，则沿用前一个窗口的 end_value。
    - start_value：前一个窗口的 end_value；对于首个窗口，使用本窗口的第一条记录 v 值。
    - min：本窗口内 v 的最小值。若本窗口无数据，则取本窗口的 end_value。
    - max：本窗口内 v 的最大值。若本窗口无数据，则取本窗口的 end_value。
预期结果：
```
start	end	start_value	end_value	min	max
10:10:00	10:11:00	3	3	3	3
10:11:00	10:12:00	3	4	4	4
10:12:00	10:13:00	4	4	4	4
10:13:00	10:14:00	4	8	5	9
10:14:00	10:15:00	8	2	2	2
```

# SQLazy 代码输出格式规范（.nsql 步骤语法）
生成的第4步分步代码，必须严格采用 SQLazy IDE 可直接运行的 .nsql 文本格式，规则如下：

## 1. 步骤语法（三要素之间无空格）
每一行 = 一个步骤，有三个要素：**命名、锚点、语句**
步骤语法是**[<命名> =] [<锚点>:] <语句>**
- 要素1「命名」：本步骤结果表的名称（如 t1、t2…，也可自定义有意义的名字），后面紧接符号"="，两者一体，供后续步骤引用；
- 要素2「锚点（焦点表）」：本步骤要处理的对象表（如t2、t3…）；后面紧接符号":",两者一体；**可为空**（留空即什么内容都不写，不是 null）。为空时默认承接上一步的结果表；
- 要素3「语句」：该步骤的 SQLazy 功能语句。

示例（下方每两列之间无空格）：
```
t1=t_1742353802112:计算列 datetime(t; 精度 分), 命名 tm
t2=排序 t
```
## 2. 每步有且仅有一个功能
每一行（每步）只能包含**一个功能**（如 计算列 / 汇总 / 对齐 / 列表 / 导出表 / 排序 …）；但语句内**函数可嵌套多个**（如 条件()、datetime()、偏移）。需要多个功能时必须拆成多步。
不需要取数步骤（即SQL功能），因为表数据已经在上下文环境中，nsql代码可以直接引用，表在nsql中的变量名和表的物理名必须一致。

## 3. 跨步引用值：命名.字段
引用其他步骤产出的值时，用「命名.字段」写法。例：`列表 头 t4.min_t 尾 t4.max_t …`（引用 t4 步骤汇总出的 min_t、max_t 字段）。

## 4. 锚点 = 焦点表
第2部分锚点即当前步骤处理的输入表。显式写出可跨步指定处理对象（例：t6 锚点写 t3，表示对 t3 表做对齐），留空则承接上一步结果。

## 5. 语句不换行
每步语句必须写在同一行内，**严禁换行**。

## 6. 保留字作命名需加单引号
min、max、end、start、date、inc、cum、sum、avg、count 等保留字若要作为命名/字段名，必须加单引号。例：`max_v 命名 'max'`。

## 7. 命名不得重复
每步命名必须唯一，不得重复。

## 8. 函数写法规则
**第一步：判断函数类型，格式二选一**
| 函数类型 | 格式 | 说明 |
|---|---|---|
| **有对象参数**（作用于某个字段/对象） | `(对象 函数词 参数...)` | 参数可省略；整体用圆括号包裹 |
| **无对象参数** | `函数词(参数...)` | 参数必须用圆括号包裹；**统一只用这种写法**，不写其他形式 |
**第二步：按类型写参数**
- 参数形式：`参数名 参数值`，参数名可省略
- 有对象函数：参数之间用**空格**分隔
- 无对象函数：参数之间用**分号**分隔
- 参数值 = 任意计算式（字段、数值、字符串、其他函数、集合），可无限嵌套
- 函数式作为复合条件（与 且/或 连用）时，必须整体加括号。例：`(prev_max 非空) 且 start_date > prev_max`
**示例**
| 类型 | 示例 |
|---|---|
| 有对象，0 个参数 | `(订单日期 为空)` |
| 有对象，1 个无名参数 | `(1980-02-27 当周末日 周一起始)` |
| 有对象，1 个带名参数 | `(2020-02-15 偏移 5)` |
| 有对象，2 个参数 | `(2020-02-15 偏移 5 月)` |
| 无对象，0 个参数 | `pi()` |
| 无对象，1 个参数 | `date("1984-02-27")` |
| 无对象，2 个参数 | `datetime("12/28/1972 10:23:43"; 格式 "MM/dd/yyyy HH:mm:ss")` |
